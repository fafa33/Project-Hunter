## What this change adds: the production entry point

### Architecture impact

None. No ADR is touched. No existing validation, formula, replay, or persistence logic is modified, duplicated, or reimplemented. The new code is a thin orchestration layer, exactly mirroring `hunter.valuation_evidence.command`'s existing design:

- `src/hunter/valuation_authority/command.py` (new) — parses an operator-authored manifest, converts JSON-safe primitives to typed arguments, and calls exactly one of the two existing, unmodified authorities:
  - `operation: "methodology"` → `CanonicalValuationMethodologyAuthority.persist_methodology(...)`
  - `operation: "estimate"` → `CanonicalValuationService.estimate_fair_value(...)`

  It performs no business validation of its own; every check (strict-known selection, missingness, conflict rejection, horizon/accounting-period compatibility, correction-lineage integrity, repository-bypass rejection) is enforced exclusively inside the two existing services, and their exceptions propagate unmodified.
- `src/hunter/valuation_authority/__init__.py` (new) — re-exports `main`, mirroring every other CLI package in the repository.
- `src/hunter/__main__.py` (modified) — adds one dispatch branch, `valuation-authority`, mirroring the existing `committee-authority`/`valuation-evidence` branches exactly.

### CLI command added

```
hunter valuation-authority run MANIFEST.json
```

Manifest schema (JSON): `{"operation": "methodology", "payload": {...}}` or `{"operation": "estimate", "identity": {...}, "evidence_type": ..., "rule_type": ..., "effective_at": ..., "recorded_at": ..., "known_at": ..., "supersedes_estimate_record_id": ..., "supersedes_assessment_record_id": ..., "correction_reason": ...}`. No field is ever defaulted to "latest"/"current" — every lookup the underlying services perform is bounded by the exact `effective_at`/`recorded_at`/`known_at` coordinates and identity fields the manifest declares.

### Authority boundaries preserved

- `hunter valuation-evidence acquire` remains the sole path for `FundamentalEvidenceRecord`/`ValueCaptureRuleSnapshot`/`SupplyBasisSnapshot`/`ObservedMarketFactRecord` — untouched by this change.
- `CanonicalValuationMethodologyAuthority` remains the sole methodology write authority — untouched; only invoked.
- `CanonicalValuationService` remains the sole write authority for `FairValueEstimateRecord`/`ValuationAssessmentRecord` — untouched; only invoked.
- `CanonicalValuationRepository`/`ValuationMethodologyRepository` still expose no public write method (verified by `test_repository_bypass_remains_impossible`).
